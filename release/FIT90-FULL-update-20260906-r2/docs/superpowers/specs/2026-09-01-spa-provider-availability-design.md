# تصميم جدول حضور مقدم خدمة السبا والحجز بالخدمة

التاريخ: 2026-09-01  
الحالة: معتمد من صاحبة المشروع

## الهدف

يحجز مسؤول السبا حضور مقدم الخدمة للشهر من دون ربطه بخدمة. عند الحجز يختار الموظف العضو ثم خدمة السبا، ويقرر النظام داخل معاملة واحدة إن كان للحجز رصيد جلسات مجاني أو أنه مدفوع عند الحضور.

## القرارات المعتمدة

- جدول السبا الشهري وفترات الحضور يرتبطان بمقدم الخدمة والشهر فقط.
- كل فترة حضور تستقبل خدمة سبا واحدة في الوقت نفسه؛ تحدد مدة الخدمة نهاية الموعد ويمنع النظام التداخل.
- الخدمة وسعرها ومدتها تحفظ كلقطة في الحجز عند إنشائه.
- رصيد جلسات السبا يحجز فور تأكيد الحجز، فيشمل الحساب الحجوزات `pending` و`confirmed` و`completed` و`no_show` التي لم يسترجع رصيدها.
- عند إلغاء حجز مغطى بالاشتراك يعاد الرصيد تلقائيًا بوضع علامة استرجاع على الحجز؛ لا يعود الرصيد للحجز المكتمل أو عدم الحضور إلا بإجراء إداري قائم.
- عند عدم وجود رصيد ينشأ الحجز بقيم `coverage_type=pay_at_branch` و`payment_status=due_at_branch` مع رسالة وسعر واضحين.
- تبقى الخدمات الإضافية مرتبطة بالخدمة الأساسية التي اختيرت عند الحجز.

## حدود التغيير

- يعاد استخدام جداول حضور مقدمي الخدمة وفترات التوفر الموجودة، مع دعم فئة `spa` بجانب `nutrition`.
- ينشأ سجل الموعد المتوافق مع المحرك الحالي لحظة تأكيد حجز السبا، كما يحدث في التغذية؛ لا يلزم تغيير مخطط قاعدة البيانات.
- لا تتغير جداول أو حجوزات الكلاسات أو التدريب الشخصي أو التغذية.

## معايير القبول

1. لا يظهر اختيار خدمة عند إنشاء جدول السبا الشهري.
2. يختار موظف الحجز خدمة سبا نشطة قبل التأكيد.
3. يعرض النظام الرصيد المتبقي أو عبارة «الحجز مدفوع» والسعر قبل التأكيد.
4. لا يمكن أن يستهلك حجزان متزامنان آخر جلسة مجانية.
5. إلغاء حجز مجاني يعيد الرصيد تلقائيًا.
