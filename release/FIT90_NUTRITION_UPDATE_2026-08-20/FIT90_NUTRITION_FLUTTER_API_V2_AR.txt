FIT90 - API التطبيق: حجز التغذية (التقويم أولاً)
=================================================

ترتيب الشاشات المطلوب
---------------------
1. اختيار أخصائي التغذية.
2. عرض تقويمه الشهري وفترات حضوره.
3. اختيار يوم/فترة حضور.
4. اختيار خدمة التغذية.
5. إظهار هل الخدمة تابعة للاشتراك أم الدفع عند الحضور.
6. عرض الأوقات المتاحة لهذه الخدمة فقط.
7. اختيار وقت وتأكيد الحجز.

Base URL
--------
https://fit90.metacodecx.com/api

كل الطلبات بعد Login تحتاج:
Authorization: Bearer <accessToken>


1) الأخصائيون
--------------
GET /mobile/app/nutrition/providers

يعرض التطبيق قائمة أخصائيي التغذية الذين لديهم حضور منشور. يختار العميل أخصائياً ويحفظ trainerId.


2) التقويم الشهري قبل اختيار الخدمة
------------------------------------
GET /mobile/app/nutrition/schedule?trainerId={trainerId}&year={year}&month={month}

مهم: لا ترسلي serviceId في هذا الطلب.

الرد:
- service = null
- days[].windows: فترات حضور الأخصائي وحالة الحجز.
- days[].times: قائمة فارغة، لأن الخدمة لم تُختر بعد.

اعرضي الأيام وفترات الحضور فقط. لا تعرضي زر حجز نهائي ولا أوقات دقيقة في هذه المرحلة.

حالة كل فترة موجودة في bookingStatus:
- booking_available: يمكن للعميل اختيار اليوم ثم متابعة اختيار الخدمة.
- booking_not_started: اعرضي وقت فتح الحجز bookingStartAt، ولا تسمحي بالحجز.
- booking_closed أو appointment_started: اعرضي الحالة ولا تسمحي بالحجز.


3) الخدمات بعد اختيار اليوم
----------------------------
GET /mobile/app/nutrition/services

يعرض التطبيق اسم الخدمة، مدتها، وسعرها. عند اختيار خدمة احفظي serviceId.


4) الاشتراك أو الدفع عند الحضور
--------------------------------
GET /mobile/app/nutrition/eligibility?serviceId={serviceId}&date={yyyy-MM-dd}

إذا كان:
- coverageType = subscription
  اعرضي أنها تابعة للاشتراك وعدد الحصص remaining.

- coverageType = pay_at_branch
  اعرضي "الدفع عند الحضور" ومبلغ amountDue.
  لا تمنعي العميل من الحجز ولا تنفذي دفعاً إلكترونياً.


5) الأوقات المتاحة بعد اختيار الخدمة
-------------------------------------
GET /mobile/app/nutrition/schedule?serviceId={serviceId}&trainerId={trainerId}&year={year}&month={month}

في هذا الطلب فقط ترسلي serviceId.

استخدمي days[].times للمواعيد القابلة للحجز. كل عنصر يحتوي:
- availabilitySlotId
- startTime
- endTime

السيرفر يحسب الأوقات حسب مدة الخدمة ويستبعد أي تعارض مع الحجوزات الموجودة.
لا تحسبي المدة أو التوفر محلياً داخل Flutter.


6) إنشاء الحجز
--------------
POST /mobile/app/nutrition/bookings

Request body:
{
  "availabilitySlotId": 11,
  "serviceId": 10,
  "startTime": "15:30",
  "notes": ""
}

خذى availabilitySlotId وstartTime من days[].times في الخطوة 5 فقط.

بعد النجاح، اعرضي:
- الخدمة والأخصائي والتاريخ والوقت والمدة.
- "تابعة للاشتراك" مع المتبقي، أو "الدفع عند الحضور" مع المبلغ.

ثم أعيدي تحميل التقويم والأوقات وحجوزاتي.


7) معالجة التعارض
-----------------
إذا عاد HTTP 409، فهذا يعني أن الوقت لم يعد متاحاً أو أن نافذة الحجز تغيرت.
اعرضي رسالة مناسبة، ثم أعيدي طلب التقويم بدون خدمة وبعده طلب الأوقات بالخدمة.


Postman
-------
استخدمي ملف:
NUTRITION_FLUTTER_POSTMAN_COLLECTION_V2.json

ويُشغّل بالترتيب نفسه: Provider -> Calendar without service -> Service -> Eligibility -> Times with service -> Booking.


ملاحظة النشر
------------
واجهة API الجديدة تعمل محلياً الآن. ستظهر على تطبيق الإنتاج فقط بعد بناء ورفع Backend الجديد وتشغيل تحديث التغذية على السيرفر باستخدام Node 20.
